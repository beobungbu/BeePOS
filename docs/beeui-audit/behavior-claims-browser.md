# BeeUI behavior claims: the 8 browser-only claims (Phase 11 Part B)

`docs/beeui-audit/behavior-claims.md` executed 72 of 80 documented "state and behavior
contract" claims against the installed `@beemvp/beeui-ui` package with Jest +
react-test-renderer. The remaining 8 depend on a real DOM, a real overlay/portal/focus
runtime, or a real timer - all of which that harness stubs out (see
`scripts/audit/claims/jest.setup.js`). This file executes those 8 with Playwright
against the actual BeePOS web build (`npx expo start --web`) instead.

Generated by running `npx playwright test -c scripts/audit/browser/playwright.config.ts`
against a hidden, unlinked `/audit` route (`app/(app)/audit/index.tsx`, delegating to
`src/features/audit/audit-harness-screen.tsx`) that mounts real BeeUI `Dialog`,
`AlertDialog`, `Select`, `Sheet` and `useToast()` instances with deterministic
`testID`s, behind BeePOS's real `BeeUIProvider`. This route is not linked from any nav
item and exists only for this suite; see that file's docblock.

Total claims covered: 8. Holds: 8. Fails: 0. Untestable-in-app: 0.

## Scope notes

- ADLG-01, DLG-02, and SHEET-01 each mention a native-only dismissal channel (Android
  hardware back / iOS native modal dismissal, or the native swipe gesture). Those
  channels are not exercisable in a browser; Phase 11 Part A's iOS Simulator pass
  covers Sheet's native swipe-to-dismiss and native back/dismiss semantics separately.
  The web-testable parts of each claim (Escape, backdrop press, the documented opt-out
  props) are fully verified here.
- No claim required the `untestable-in-app` fallback: the real app's own components
  (Dialog, AlertDialog, Select, Sheet, Toast provider) were sufficient once mounted with
  the right props/scenario; nothing needed mocking.
- Full command evidence and console/DOM excerpts are in
  `plans/260911-0854-beepos-ui-prototype/reports/phase-11-native-browser-report.md`.

## Worker A · doc-truth verifier (machine evidence)
### A1 Params accuracy, all 62 components
Script `scripts/audit/check-props-vs-dts.mjs`: for each component page `/docs/components/<slug>/`, parse every Props table (prop, type, default, required) and compare with the `.d.ts` interface for each exported symbol (use the `typescript` package, v6 is installed, to resolve the real prop type of `React.ComponentProps<typeof X>` including inherited RN props; treat "Also carries every prop of RNXProps" statements as the documented inheritance). Output `docs/beeui-audit/props-accuracy.{md,json}` with per-component totals and the full diff list.
### A2 Behavior claims, executable
For the components BeePOS uses (see prompt list) plus every component whose page has a "State and behavior contract" or "Accessibility" section with concrete, testable statements: extract each claim (e.g. "disabled or loading both block press handling", "controlled usage without onValueChange warns in development", "Web gets a focus trap", "Escape closes the deepest scope", "TableRow is a plain View"), and write a Jest test per claim under `scripts/audit/claims/__tests__/<component>.claims.test.tsx` using the project's jest-expo setup (RNTL + `@testing-library/react-native`; check what is installed, do not add packages; if the web-only claims need jsdom and it is not available, mark those claims `untested-needs-browser` and list them for Worker B's Playwright pass). Each test's `it()` title starts with the claim ID so the report can map it back. Record results in `docs/beeui-audit/behavior-claims.{md,json}`: claim, source URL + quoted sentence, test file, result `holds | fails | untested-needs-browser | untestable`, and for failures the observed behavior.
### A3 Reality column for the matrix
Extend `scripts/audit/build-docs-llms-matrix.mjs` (or a follow-up script `apply-reality.mjs`) to add `reality` and `verdict` fields to every row: `reality` = what the npm package / runtime shows (from A1, A2, `check-exports-vs-dts`, `npm view`, phase findings), `verdict` ∈ `docs-right | llms-right | both-wrong | both-right | reality-unknown`, plus `fix` = one-line sync proposal. Then summarise: counts per verdict, the list of `both-wrong`, the list of `docs-right` where llms must change, the list of `llms-right` where docs must change.
